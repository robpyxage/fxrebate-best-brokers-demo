# Security review — FXRebate static prototype

Scope: repository source, static assets, local preview server and deployment headers. This is a targeted review, not an independent penetration test or assessment of the client's production system.

- The client-side interactions use DOM text setters rather than HTML insertion, do not send worksheet entries to a server, and escape spreadsheet formula-like entries on CSV export.
- Broker profile links now reject non-HTTPS, protocol-relative and credential-bearing URLs. The link target still needs business validation when source data changes.
- The local preview server now binds to loopback by default, serves GET/HEAD only, rejects hidden paths and follows real paths only inside the output directory. It remains a development server, not a production server.
- The generated Vercel configuration adds CSP, frame protection, referrer and permissions policies. CSP permits inline styles because generated chart visualizations use inline style attributes; it blocks inline and external scripts by default. CSP needs reevaluation when real-site integrations are added.
- Confirmed blocked requests for `.env.local`, `.vercel/project.json`, encoded hidden names and `.gitignore`. Browser tests with the CSP simulated on responses passed for representative About, Careers, ranking, rebates, decision guide and educational pages; theme toggle passed.
- The demo and repository are public. Noindex is not access control. Recruitment, authentication, real analytics, CMS and live broker data are outside the prototype and require separate security review upon integration. Financial content and rates require client review.
- The client approved publication of these changes through the established GitHub/Vercel workflow.

## Credentials and repository checks

- Checked tracked filenames and scanned tracked text for common private-key, AWS, GitHub and OpenAI key formats; no matches were found. This is a pattern-based check, not a guarantee that all possible secrets have been detected.
- The current `.env.local` and Vercel project configuration are ignored. Public HTTP requests to `.env`, `.env.local`, `.vercel/project.json` and `.git/config` returned 404. No environment values were printed.
- Added ignore patterns for common private keys, local secrets folders and credential files for Git and Vercel deployments. Historical filename checks for the known local environment and Vercel config paths returned no tracked commits.
- Source content and compiled pages in the GitHub repository are intentionally public. Do not place sensitive material in those files.

## Follow-up: comparison with LOGIS and production integration

The local Vercel build configuration adds `payment=()` and `usb=()` to Permissions-Policy because the prototype does not use either browser capability, and adds `upgrade-insecure-requests` to its CSP. Verify actual production headers after the next authorized deployment. These policies may need adjustment for real payment or other integrations; do not copy the demo CSP unchanged into the application. The local static site continues to permit inline CSS for diagram styles while scripts must be same-origin. LOGIS uses a framework-specific nonce for its Next.js rendering; assess that approach in the actual FXRebate framework rather than copying it into this static prototype.

For the production website, the implementing team should design and test server-side input validation, contextual output escaping, authentication and authorization for account and admin endpoints, session security, appropriate CSRF/origin checks, request size limits, durable rate limiting and anti-automation appropriate to each form/API, secure secrets management, data retention and monitoring. Turnstile or similar checks should be verified server-side where adopted. Validate provider links, integrations, CSP, referrer/frame policies, third-party access and deployment secret isolation in the actual environment. Review risks and policies before enabling any feature; these are integration requirements, not functions of the demo and not claims of implemented production protection.
